# Telegram Warmup Bot

Автоматизированный бот для комментирования в Telegram-каналах с поддержкой «прогрева» аккаунтов и гибкого расписания работы. Проект построен на [Aiogram 3](https://docs.aiogram.dev/) для управления ботом и [Pyrogram](https://docs.pyrogram.org/) для взаимодействия с аккаунтами.

## Основные возможности

- 🤖 Автоматическое комментирование постов в каналах Telegram.
- 🧠 Генерация текстов комментариев через OpenAI API.
- 🌡️ Режим прогрева для новых аккаунтов: постепенное подключение каналов, дневные лимиты и интервалы.
- ⏱️ Циркадные паузы: общий «тихий» промежуток времени, когда комментарии не отправляются.
- 🛠️ Гибкое управление очередью прогрева и настройками аккаунтов прямо из интерфейса бота.
- 📝 Сводные отчёты, логи пропусков комментариев и автоматическая очистка устаревших записей в базе.
- 🔐 Доступ по паролю и хранение сессий в локальных файлах.

## Требования

- Python 3.10 или новее.
- Установленный [pip](https://pip.pypa.io/) и виртуальные окружения (`venv`).
- Telegram API credentials (API ID / API HASH) и токен бота.
- Ключ OpenAI API для генерации комментариев.
- SQLite (по умолчанию) или PostgreSQL, выбираемые через `DATABASE_URL`.

## Быстрый старт (локальный запуск)

1. **Склонируйте репозиторий**:
   ```bash
   git clone <ваш-git-url>/telegram-warmup-bot.git
   cd telegram-warmup-bot
   ```

2. **Создайте и активируйте виртуальное окружение**:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate  # Windows: .venv\Scripts\activate
   ```

3. **Установите зависимости**:
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. **Скопируйте шаблон настроек и заполните `.env`**:
   ```bash
   cp .env.example .env
   ```

   Минимальный набор переменных:
   ```env
   BOT_TOKEN=токен_вашего_бота
   API_ID=ваш_api_id
   API_HASH=ваш_api_hash
   OPENAI_API_KEY=ключ_openai
   PASSWORD=пароль_для_доступа_к_боту
   # Для SQLite
   DATABASE_URL=sqlite:///data/CDXBOT0310.db
   # Для PostgreSQL
   # DATABASE_URL=postgresql://pgbot1010_user:pgbot1010_password@postgres:5432/pgbot1010
   ```

   Дополнительно доступны:
   - `WARMUP_VERBOSE_LOGS=1` — подробные логи в консоли.
   - `WARMUP_VERBOSE_NOTIFICATIONS=1` — расширенные уведомления в лог-канал.
   - `REACTION_LIMIT_PER_MESSAGE`, `REACTION_MIN_INTERVAL_SECONDS` — лимиты реакций.

   > 💡 По умолчанию `docker-compose` создаёт базу данных `pgbot1010` с пользователем `pgbot1010_user`.
   > Эти же значения используются в `.env.example` и в переменной `DATABASE_URL`.

5. **Проверьте файл расписания `schedule.json`** — в нём задаются тихие периоды и окно прогрева. Значения по умолчанию:
   ```json
   {
     "quiet_period": {
       "start_hour": 21,
       "start_minute": 30,
       "end_hour": 3,
       "end_minute": 40,
       "description": "Режим тишины - бот не комментирует в это время (00:30-06:40 МСК = 21:30-03:40 UTC)"
     },
     "warmup_period": {
       "start_hour": 1,
       "start_minute": 0,
       "end_hour": 3,
       "end_minute": 0,
       "description": "Период прогрева - бот вступает в каналы в это время (04:00-06:00 МСК = 01:00-03:00 UTC)"
     },
     "warmup_settings": {
       "channels_per_day": 15,
       "delay_minutes": 7,
       "default_days": 7,
       "description": "Настройки режима прогрева"
     }
   }
   ```
   Файл подхватывается автоматически при старте и может редактироваться без перезапуска бота.

6. **Запустите бота**:
   ```bash
   python main.py
   ```

   При первом запуске бот попросит пароль (`PASSWORD` из `.env`). После авторизации станет доступна клавиатура с основными действиями.

## Команды и сценарии

- `/start` — авторизация и вывод главного меню.
- `/summary <номер>` — краткая сводка по конкретному аккаунту.
- `/testwarmup` — ручной запуск проверки очереди прогрева.
- `/cleansessions` — удаление неиспользуемых сессий Pyrogram.
- `/fixmode` — выводит список аккаунтов, застрявших в прогреве, и переключает их в стандартный режим.
- Кнопка **«Добавить аккаунт»** — пошаговая привязка нового аккаунта, настройка задержек, шансов и промптов.
- Кнопка **«Добавить прогрев»** — помещение каналов в очередь прогрева без изменения основного режима.
- Кнопка **«📊 Общая статистика»** — отчёт по всем аккаунтам и журнал пропусков.
- Кнопка **«⚙️ Настройки прогрева»** — редактирование глобальных лимитов и окна вступления в каналы.

## Структура проекта

- `main.py` — основной сценарий бота, обработчики команд и управление прогревом.
- `comment_engine.py` — интеграция с OpenAI и генерация комментариев.
- `db.py` — асинхронный слой работы с SQLite/PostgreSQL, миграции и бизнес-логика БД.
- `schedule.json` — настраиваемое расписание «тихих» периодов и окна прогрева.
- `deploy.sh` — сценарий автоматического развёртывания на VPS (создание виртуального окружения, systemd-сервис и т.д.).
- `docker-compose.yml` — запуск бота в контейнере с монтированием данных и расписания.
- `fix_mode.py` — вспомогательный скрипт для смены режима аккаунтов вне бота.
- `tests/` (файлы `test_*.py`) — модульные тесты ключевых сценариев.

## Развёртывание

### Systemd (скрипт `deploy.sh`)
Сценарий развёртывания устанавливает зависимости, создаёт виртуальное окружение, настраивает `CDXBOT0310.service` и утилиту `manage.sh`. Запустите его из каталога проекта:
```bash
chmod +x deploy.sh
./deploy.sh
```
После выполнения будут доступны команды:
```bash
./manage.sh start    # Запуск сервиса
./manage.sh stop     # Остановка
./manage.sh restart  # Перезапуск
./manage.sh status   # Статус
./manage.sh logs     # Просмотр логов через journalctl
./manage.sh update   # git pull + обновление зависимостей
```

### Docker Compose
```bash
docker-compose up -d --build   # Сборка и запуск контейнера
docker-compose logs -f         # Просмотр логов
```
В контейнер пробрасываются каталоги `sessions/`, `logs/`, `data/` и файл `schedule.json`.

## Логи и отладка

- Логи комментариев и ошибок доступны в базе (`comment_logs`) и в лог-канале Telegram.
- Переменные `WARMUP_VERBOSE_LOGS` и `WARMUP_VERBOSE_NOTIFICATIONS` помогают включить расширенную диагностику.
- Скрипт `fix_mode.py` можно запускать вручную для принудительного выхода аккаунтов из прогрева.
- Для очистки устаревших записей комментариев используется автоматическая задача (по умолчанию каждые 6 часов).

### Настройка реакций

- Таблицы `posts` и `reaction_logs` создаются автоматически при первом подключении к базе данных. Они используются для отслеживания обработанных постов и состояний реакций (успех, пропуск, ошибка).
- Перед выдачей реакций убедитесь, что аккаунт находится в статусе `running` и включает реакции:
  ```sql
  UPDATE accounts
  SET status = 'running', reactions_enabled = TRUE
  WHERE id = 1;
  ```
- Основные параметры хранятся в таблице `accounts` и могут настраиваться напрямую:
  ```sql
  UPDATE accounts SET
      reaction_chance = 70,
      reaction_discussion_chance = 80,
      discussion_reply_chance = 50,
      discussion_reply_prompt = 'Ты молодец',
      reaction_sleep_min = 30,
      reaction_sleep_max = 90,
      reaction_emojis = '["❤️", "👍"]',
      reaction_limit_per_message = 8,
      reactions_enabled = TRUE
  WHERE id = 1;
  ```
- Настройки из интерфейса бота автоматически синхронизируются с колонками `accounts`. При необходимости можно использовать метод `bulk_update_reaction_settings` для массового применения.

### Мониторинг реакций

- Все попытки реакций логируются в таблицу `reaction_logs`. Поле `status` принимает значения `success`, `skipped` или `failed`, а `error_message` содержит пояснения.
- Для оперативного контроля можно использовать SQL-запросы:
  ```sql
  SELECT status, COUNT(*)
  FROM reaction_logs
  WHERE account_id = 1
  GROUP BY status;
  ```
- Аналитика по реакциям также попадает в `comment_logs`, поэтому существующие отчёты остаются совместимыми.
- Живые логи удобно просматривать через Docker или journalctl:
  ```bash
  docker logs bot_container | grep -i "reaction"
  docker logs bot_container | grep -i "error"
  ```
